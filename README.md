[Key Learning]
1) async/await: 따로 개인적인 프로젝트를 진행할 때 setTimeout() 함수를 사용해본 적이 있었는데, delay를 발생시켜 다음 코드의 실행을 뒤로 미뤄줄 수 있을 것이라는 개인적인 기대와는 달리,
                setTimeout() 내부의 함수만 지연이 되고 나머지 함수는 동시에 실행이 되는 것을 보며 의아했었다. 오늘 async와 await 키워드를 학습하며, 동기와 비동기 실행에 대해 학습하였고,
                해당 현상에 대해 보다 깊이 이해할 수 있게 되었다.
2) fetch(): fetch()함수를 이용해 서버에 요청을 보내는 법을 학습하였다. 이때, 여러 method를 이용해 단순 데이터를 전송받는 것뿐만 아니라,
            데이터를 보내기도, 업데이트할 수도 있다는 점을 배웠다. POST나 PATCH는 문법 구문을 어느정도는 숙지하고 있어야 빠르게 사용할 수 있을 것 같다.
3) JSON: json 데이터 형식을 통해 각기 다른 웹사이트일지라도 통일된 형식으로 편리하게 데이터를 주고받을 수 있다는 점을 학습하였고, 이를 실제로 json데이터로 변환하고, json데이터를 배열로 변환하는 방법을 실습하였다.

[Problem&Solution]
처음엔 하드 코딩으로 틀만 짜기에서, 배열을 이용해 기본적인 CRUD 기능 구현으로, 그리고는 이제 실제 서버와 데이터를 주고받기까지. 
한단계씩 점차 실제 웹사이트 구현에 가까워지는 점이 흥미로웠고 재밌었다. 또한 현재 수업에서 학습하고 있는 이 내용을 기반으로 
개인적인 다른 프로젝트를 진행하고 있는데, 학습한 내용을 나만의 실제 프로젝트를 위해 사용할 수 있다는 점이 개인적으로 가장 크게 흥미롭게 다가왔다. 

이번 과제를 수행하며 마주한 가장 큰 문제는, 기존에 이미 CRUD 서비스를 구현하기 위해 작성했던 코드를 서버와 소통하는 코드로 수정하는데에 있었다. 
기존에 배열을 다루기 위해 사용했던 함수들을 모두 서버와 소통하는 함수로 바꾸는 과정에서 코드가 꼬이기도 하고 변수 이름이 헷갈리기도 하는 등, 여러 문제가 있었다. 
특히 editID와 editIndex를 혼용해 사용함으로 인해 버그가 지속적으로 발생했는데, 해당 사실을 인지하지 못 해 한동안 수정을 하고난 후에 editIndex가 초기화되지 않아 신규 데이터를 생성하면
수정을 진행했던 해당 데이터에 새로운 데이터가 생성하는 버그가 발생하기도 했다. 결국 처음부터 코드를 다시 쭉 읽어보며 코드 흐름을 그려보고 난 후에야 발견할 수 있었다.
